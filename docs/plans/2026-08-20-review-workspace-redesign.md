# 本地 Code Review 工作区重设计

## 目标

- 审查历史与当前文件勾选状态解耦，任何时候都能读取当前仓库的 SQLite 会话。
- 新建审查、历史报告、自定义规则形成稳定的信息架构，不再挤在顶部 Tab 和长滚动页中。
- 保持“本地关注度选文件 → 用户勾选 → AI Review”的产品逻辑。
- 正常请求不增加 Token；仅在模型返回空内容或不完整 JSON 时进行一次纠错重试。

## 交互结构

Review 使用 macOS 工具窗口的 Sidebar + Content 结构：

- 左侧：新建审查、最近会话、审查规则。
- 右侧新建页：选中文件摘要、预算选择、启动操作。
- 右侧报告页：会话状态、严重度概览、处理状态筛选、Finding、诊断限制、审查文件。
- 右侧规则页：规则编辑表单与规则列表。

打开 Review 只要求当前存在仓库快照，不要求已经勾选文件。只有“开始审查”要求至少选择一个文件。

- 当前已勾选文件时，默认进入“新建审查”。
- 当前未勾选文件时，默认打开最近一条 SQLite 历史；没有历史时显示历史空状态。

## AI 响应容错

- DeepSeek V4 使用官方 `thinking.type=disabled` 关闭默认开启的思考模式，避免 reasoning 耗尽输出预算后留下空正文。
- 其他 OpenAI-compatible 模型使用 `enable_thinking=false`，并同时使用支持 Qwen/vLLM 的 `chat_template_kwargs.enable_thinking=false`。
- 如果接口明确不支持该字段，则移除后自动重试。
- 支持字符串和数组形式的 `message.content`。
- reasoning 不会被当成最终 JSON；`finish_reason=length` 时使用关闭推理的纠错请求重新获取结构化结果。
- 识别空内容、缺失完整 JSON 对象和 `finish_reason`。
- 仅对空内容或格式不完整的结果进行一次短纠错重试。
- 大文件截断改为保留 diff 头部与尾部，中间裁剪，避免只看到文件前半段。

## 源代码核验与定位

- 采用 Alibaba OpenCodeReview 的“确定性管线 + 模型判断”思路，但保持 Lumina 单次请求的轻量模式。
- 每个文件同时提供 Diff 与受预算控制的当前源文件上下文；优先完整源文件，超限时保留文件头、文件尾和改动行附近窗口。
- 模型报告“缺少清理、重置、校验或错误处理”前必须检查当前源文件；上下文不足时不允许猜测。
- 模型必须返回最小的 `existingCode` 代码锚点，后端忽略模型自报行号，在当前源文件中重新定位。
- 代码锚点必须唯一匹配并覆盖真实改动行；无法定位、存在歧义或只指向未改代码的 Finding 直接丢弃。
- 准确率优先于召回率：宁可不展示推测性问题，也不让用户处理没有源代码证据的误报。

## 快捷键展示

按钮旁不再常驻展示快捷键。快捷键行为保留，并集中放在“设置 → 快捷键”中，根据 Windows/Linux 与 macOS 显示 Ctrl 或 Command。

## 验收

- 未勾选文件时仍可进入 Review 并查看历史和规则。
- 历史会话可从左侧直接切换，报告不会依赖当前工作区选择。
- 空 content 不再直接产生 `EOF while parsing a value`。
- 诊断区域明确区分 diff 截断与 batch 调用失败。
- 刷新、提交、Review 按钮旁不显示快捷键提示。
