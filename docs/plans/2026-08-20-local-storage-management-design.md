# Lumina 本地存储管理设计

## 目标

Lumina 保持离线优先，用户数据不依赖在线服务。应用提供统一的本地存储设置，让用户能够查看当前磁盘占用、配置历史数据的默认保留期限，并手动清理已经过期的数据。

## 数据边界

自动清理只处理具备明确生命周期、可以安全删除的数据：

- Git 提交文案历史；
- DevDock 最近命令历史；
- Lumina 专属缓存目录中的过期文件；
- 超过保留期限的应用日志。

以下内容不参与自动清理：

- AI 模型和应用偏好；
- 项目配置、别名和置顶状态；
- 用户收藏或明确保存的成果；
- 用户主动导出的文件；
- 用户项目目录中的任何文件。

## 设置模型

- 自动清理默认开启；
- 默认保留期限为 90 天；
- 用户可以设置 1 至 3650 天；
- 关闭自动清理等价于不按时间自动过期；
- 启动应用时检查一次，持续运行期间每 24 小时复查；
- 手动清理不受自动清理开关影响，但仍只删除超过当前保留期限的数据。

设置保存在 Tauri 应用配置目录的 `storage-settings.json` 中。最后清理时间一并持久化，用于避免在短时间内重复扫描。

## 占用统计

设置界面展示以下类别：

- 应用数据：预留的 SQLite 数据库及应用数据目录；
- 缓存：Lumina 专属缓存目录；
- 日志：Tauri 应用日志目录；
- 配置：Lumina 管理的配置文件；
- 界面数据：WebView `localStorage` 中的数据。

统计仅覆盖 Lumina 明确拥有的路径，避免 Tauri 在部分平台把配置目录和数据目录映射到相同位置时重复计数。

## 界面设计

本地存储页采用 macOS System Settings 风格，不在现有应用窗口内重复模拟标题栏或交通灯：

- 页面引导区使用系统工具图标、标题和单行说明；
- 存储概览使用实体卡片承载总量、连续分段占用条和分类图例；
- 刷新作为 28px 圆形工具按钮放在概览右上角；
- 自动清理和保留期限采用连续分组设置行，图标、说明和控件保持稳定对齐；
- 手动清理独立为低强调危险操作区，避免与普通设置混淆；
- 所有颜色、圆角、阴影和动画使用 Lumina 现有语义 Token，同时适配浅色、深色和减少动态效果模式；
- 窄窗口下分类图例切换为单列，设置行和清理操作允许自然换行。

## 失败处理与安全约束

- 清理逻辑不跟随符号链接；
- 缓存清理固定在 `app_cache_dir/lumina`；
- 日志清理固定在 Tauri 应用日志目录；
- 文件删除或设置写入失败时向前端返回错误，不把失败报告为成功；
- 无法解析的旧 `localStorage` 记录保持原状，避免因格式未知而误删；
- 当前版本不清理用户项目内的 `.lumina` 配置。

## 后续演进

引入 SQLite 后，运行历史、AI 任务和代码审查记录应统一增加 `created_at`、`expires_at`、`is_pinned` 字段。清理服务按照 `expires_at` 删除未固定记录，设置面板继续复用当前的保留期限和占用统计接口。
